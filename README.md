# Personal research website

A minimal bilingual (English / Japanese) academic homepage for **Machiko Hirota / 廣田 真知子**.

Plain HTML and CSS generated by a single ~370-line Node script. No frameworks, no npm
dependencies, no JavaScript on the published pages, no analytics.

- English: `/`
- Japanese: `/ja/`

## Running it locally

Requires Node 18+ (nothing to install).

```bash
node build.js --serve     # build + preview at http://localhost:8080
node build.js             # build only, into dist/
```

The Japanese version is at <http://localhost:8080/ja/>.

`dist/` is regenerated from scratch on every build and is git-ignored — never edit
files in there, edit the content files instead and rebuild.

Every build prints any remaining placeholders, unpublished drafts and open TODOs.

## Project layout

```
content/            <- everything you will normally edit
  site.json           name, subtitle, contact links, photo, SEO/OG metadata, UI labels
  research.json       publications, ongoing research, projects, funding
  bio.en.md           English introduction
  bio.ja.md           Japanese introduction
assets/
  style.css           the entire stylesheet
  favicon.svg         favicon
  (profile photo goes here)
build.js            generator + preview server
dist/               generated output — do not edit
.github/workflows/  GitHub Pages deployment, runs on every push to main
TODO.md             local working checklist (untracked)
```

## Updating publications and research

Everything lives in `content/research.json`, in five arrays that map onto the
subsections of the Research section — `publications`, `talks`, `writing`, `ongoing`
and `projects` — plus `funding`. Entries appear on the page in array order, so reordering
the JSON reorders the page.

They render in the order Publications, Talks, Blog Posts, Ongoing Research, Projects —
set in `build.js`, in the `<section>` markup.

A subsection with no visible entries is omitted from the page entirely, heading and
all. That is why there is currently no "Projects" heading — the `projects` array is
empty. Add an entry and the heading appears on its own.

A publication looks like this:

```json
{
  "id": "short-slug",
  "title": "Paper Title",
  "url": "https://arxiv.org/abs/...",          // optional; makes the title a link
  "authors": ["First Author", "Machiko Hirota"],
  "venue": { "en": "NeurIPS 2026", "ja": "NeurIPS 2026" },
  "note": { "en": "", "ja": "" },              // optional one-line description
  "links": [
    { "label": { "en": "Paper", "ja": "論文" }, "url": "https://..." }
  ]
}
```

Notes:

- Your own name is bolded automatically — it is matched against `authorHighlight`
  at the top of the file, so it must be spelled the same way in the author lists.
- Footnote markers on author names work: write `"Ajay Agarwal*"` and add
  `"authorsNote": { "en": "*equal contribution", "ja": "*同等の貢献" }`. The marker is
  ignored when matching your own name.
- A link with an empty `url` is skipped, so you can leave `[Code]` / `[Paper]` rows
  in place until the URL exists.
- `"draft": true` keeps an entry in the file but off the website. Use it for work
  whose title or author list is not final. The build lists all drafts.
- `"todo": "..."` is a private reminder printed by the build. It is never rendered.
- Ongoing-research, project and blog-post entries share a simpler shape: `title`, `url`,
  `meta` (an affiliation or byline), `note` and `links`, each with `en` / `ja`
  variants. Writing entries are usually just a linked title plus `meta`.

Run `node build.js` after editing; a JSON syntax error is reported immediately.

## Updating the biographies

Edit `content/bio.en.md` and `content/bio.ja.md`. Blank lines separate paragraphs;
`[text](url)`, `**bold**` and `*italic*` work. A block of lines each starting with
`* ` becomes a bullet list. Keep the two files in sync.

Affiliations mentioned in the bio are plain prose — there is no separate employment
timeline to update.

## Contact links

In `content/site.json` under `contact`:

```json
"contact": {
  "email": "you@example.com",
  "scholar": "https://scholar.google.com/citations?user=YOUR_ID",
  "github": "https://github.com/yourusername"
}
```

An empty value means the link is simply not shown (and the build warns about it), so
no dead links ever ship. All three are currently empty, leaving just the language
switcher in the header. Link labels are in `ui.en` / `ui.ja` in the same file.

## Slides, posters and other files

Drop the file in `assets/files/`. Everything in that directory is published at
`/files/`, so `assets/files/my-talk.pdf` becomes `files/my-talk.pdf`:

```json
"links": [
  { "label": { "en": "Slides", "ja": "スライド" }, "url": "files/my-talk.pdf" }
]
```

Write the URL site-relative, without a leading slash — the build rewrites it per page
so the link works from `/ja/` too.

## Profile photo

1. Put the image in `assets/`, e.g. `assets/profile.jpg` (square, ~400×400 is plenty).
2. Set `"photo": "profile.jpg"` under `site` in `content/site.json`.

Until then a neutral placeholder circle is shown. The photo is also used for the
Open Graph preview image once `site.url` is set.

## Keeping it unlisted while you edit

`content/site.json` → `site.noindex` is `true` by default. It emits
`<meta name="robots" content="noindex, nofollow">` on both pages and a `robots.txt`
that disallows everything, so a site that is temporarily up does not end up in search
results. Set it to `false` for the real launch.

That is a request to crawlers, not access control. Anyone with the URL can still open
the page. To have nothing reachable at all, keep the repo private and preview locally
with `node build.js --serve`.

To take a published GitHub Pages site back down: Settings → Pages → **Unpublish site**
(or delete the `github-pages` environment under Settings → Environments). Making the
repository private also takes the site down on plans where private-repo Pages is not
available.

## Deploying

**GitHub Pages.** `.github/workflows/deploy.yml` builds the site and publishes
`dist/` on every push to `main`. It needs the repository to be public (on the free
plan) and Settings → Pages → Source set to **GitHub Actions**.

Pushing changes to anything under `.github/workflows/` requires the `workflow` OAuth
scope: `gh auth refresh -h github.com -s workflow`, run from a normal terminal — the
device prompt needs a real TTY. Editing the file through the GitHub web UI avoids
this entirely.

Keep `"url"` in `content/site.json` pointing at the live address — it drives the
canonical, `hreflang` and Open Graph tags. **If the GitHub username or repository
name ever changes, update it**, since the Pages address changes with them.

**Any other static host.** Run `node build.js` and upload `dist/`. For Vercel or
Netlify: build command `node build.js`, output directory `dist`.

**Custom domain.** Add a `CNAME` file containing the domain to `assets/`, copy it in
`build.js` alongside the other assets, and configure the domain in Settings → Pages.
